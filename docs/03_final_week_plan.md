# 최종 프로젝트 1주 실행 계획 (D1 → D7 발표)

> **한 문장 목표**: MPU-6050 정강이 각속도에 Butterworth · 1€ · 칼만 필터를 **실시간 / 고정지연 / 사후**로 적용해,
> 벤치 리그와 사람 보행에서 **"얼마나 기다리면(d) 사후 수준의 HS 검출 정확도를 얻는가(d\*)"**를 측정하고,
> 그 차이를 **발표장에서 눈으로(바늘·실시간 그래프) 보여 준다.**

중간발표 자료는 그대로 둔다. 연구 흐름은 실험 결과에 따라 바뀔 수 있으므로, 이 계획은 **매일 끝에 "완료 기준"으로 점검하고 막히면 Plan B로 넘어가는 방식**으로 짰다.

## 1. 시스템 구성

```
 [Arduino Uno]  액추에이터 담당                     [STM32 Nucleo-F446RE]  센서·실시간 필터 담당
  · 표준 서보 → 정강이 모사 암 (보행 패턴)            · MPU-6050  INT 인터럽트로 100 Hz / 1 kHz 읽기
  · 진동모터 PWM                                     · 내부 AAF(DLPF) 켬/끔
  · HS/TO/SYNC 참값 펄스 ───────── D7 → D3 ─────▶    · 실시간 필터: Butterworth, 1€, 칼만, FIR(고정지연 d)
  · 동기 LED (카메라용)                              · 참값 펄스를 µs로 타임스탬프 (같은 시계)
  · 버튼: 프리셋 0–4                                 · 바늘 서보 2개 (RAW / FILTERED), 버튼으로 필터 선택
          │ USB 115200                                       │ USB 921600 (CSV)
          └──────────────────────── [PC] ─────────────────────┘
               · log_serial.py  : 실험 기록
               · live_view.py   : 실시간 그래프·흔들림 막대·지연 표시 (데모)
               · analyze.py     : 오프라인으로 모든 필터 × 시점 재계산 → 지표·그림·통계
               · video_events.py: 100 fps 영상의 LED·HS·TO 주석
```

- **실시간 vs 오프라인의 역할**
  - STM32는 인과(실시간) 필터 4종을 실제로 돌려 데모와 연산 시간을 담당한다.
  - 지연–정확도 비교는 같은 원자료(raw)에 PC가 모든 필터 × 시점을 다시 적용해 계산한다. 이렇게 하면 조건 간 비교가 공정하다.
  - 두 구현은 같은 식이다. MCU 코드와 PC 코드의 출력 차이가 0.0001 deg/s 이하임을 확인했다 (§8).
- **필터 설정 (기본값, 실험 중 고정)**

| 계열 | 실시간 (causal) | 고정지연 (d 샘플 대기) | 사후 (offline) |
|---|---|---|---|
| Butterworth | 2차 IIR, fc = 10 Hz | 선형위상 FIR (Hamming, 길이 2d+1, fc 10 Hz) | 영위상 filtfilt (fc 보정 0.802) |
| 1€ | min_cut 8 Hz, β 0.01, d_cut 10 Hz | 전방 1€ + 길이 4d 창 역방향 1€ 평균 (제안 변형) | 전방·역방향 평균 |
| 칼만 (등속 모델) | KF, q/R = RTS의 −3 dB가 10 Hz가 되도록 | 고정지연 스무더 | RTS 스무더 |

- **d 후보**: 1, 2, 3, 5, 8, 10, 15 샘플 = 10–150 ms (100 Hz)

## 2. 실험 설계

공통 규칙:
- 파일명은 `E<번호>_<조건>_r<반복>.csv` 형식으로 하고 `data/`에 저장한다.
- 실험마다 `docs/lab_notebook.md`에 시각, 조건, 특이사항을 한 줄씩 남긴다.
- 매 실험 전 STM32에 `b`(바이어스 재측정)를 보내고 2초간 정지한다. `log_serial.py --cmd b`로 해도 된다.

### E1. 정지 잡음: 센서가 원래 얼마나 흔들리는가

| 항목 | 내용 |
|---|---|
| 목적 | 기본 잡음 σ와 칼만 측정 잡음 R을 정한다. AAF 켬/끔에 따른 잡음 차이를 본다 |
| 조건 | 리그 `P0`(0° 유지, 진동 끔) × AAF {켬, 끔} |
| 반복 | 조건당 60 s × 3회 = 6파일 (약 15분) |
| 명령 | `python log_serial.py --port COM5 --rig-port COM6 --rig-cmd P0 --cmd a1 --cmd b --sec 60 --out ../data/E1_static_aaf1_r1.csv` |
| 분석 | `python analyze.py static ../data/E1_*.csv --out ../results/E1` |
| 산출 | `noise_psd.png`, 표(σ, 피크-피크, 주 피크), **R 추천값** |
| 성공 기준 | 정지 σ가 0.03–0.2 deg/s 범위 (MPU-6050 데이터시트 잡음 밀도 0.005 °/s/√Hz × 대역폭으로 어림) |

### E2. 진동과 앨리어싱: 왜 사전(센서 내부) 필터가 필요한가

| 항목 | 내용 |
|---|---|
| 목적 | ① 진동 주파수 f_vib를 측정한다. ② AAF가 꺼져 있으면 고주파 진동이 저주파로 접혀 들어오고, 사후 디지털 필터로는 지울 수 없음을 보인다 |
| 단계 1 | `P1`(정지 + 진동), STM32 `r1000` + `a0`로 10 s 기록 → `analyze.py static`의 주 피크 = f_vib |
| 단계 2 | 100 Hz에서 접힌 주파수가 2–5 Hz가 되게 리그 `v`(진동 PWM)를 조정한다 |
| 단계 3 | `r100` × AAF {켬, 끔} × 30 s × 3회 = 6파일 |
| 분석 | `python analyze.py vib ../data/E2_*.csv --out ../results/E2` |
| 산출 | `noise_psd.png`(접힌 피크), `shake_bar.png`(raw·필터별 흔들림 막대) |
| 성공 기준 | AAF 끔에서 접힌 피크가 뚜렷하고, 그 크기가 실시간·사후 필터를 거쳐도 거의 줄지 않는다 (가상 데이터에서 14 → 13–16 deg/s). AAF 켬에서는 해당 피크가 사라진다 |

### E3. 벤치 보행: 핵심 실험, 참값이 확실한 반복 보행

| 항목 | 내용 |
|---|---|
| 목적 | 필터 × 시점 × d마다 HS 실효 지연, 지터, 파형 오차를 구하고 d\*를 정한다 |
| 조건 (4개) | C1 `P2`류 보행(충격 없음) · C2 `P3` 보행 + 충격 · C3 `P4` 보행 + 충격 + 진동(AAF 켬) · C4 C3에서 AAF 끔 |
| 반복 | 조건당 60 s × 3회 = 12파일. 60 s당 약 50보폭이므로 조건당 약 150보폭 |
| 참값 | Arduino 명령 펄스. 서보의 일정한 지연은 분석에서 자동으로 뺀다 (사후 기준 대비 중앙값) |
| 명령 | `python log_serial.py --port COM5 --rig-port COM6 --rig-cmd P3 --cmd a1 --cmd b --sec 60 --sync --out ../data/E3_C2_r1.csv` |
| 분석 | `python analyze.py gait ../data/E3_C2_*.csv --out ../results/E3_C2` (조건별), 전체 묶음도 1회 |
| 산출 | `latency_accuracy.png`, `stride_example.png`, 표, d\*(계열별), Friedman·Wilcoxon |
| 성공 기준 | 조건마다 HS 참값 140개 이상 매칭. 고정지연 계열의 지연–오차 곡선이 단조롭게 내려와 사후 수준에 닿는다 |

### E4. 사람 보행 (권장): 실제 보행에서도 성립하는가

| 항목 | 내용 |
|---|---|
| 대상 | 최소 1명(본인), 가능하면 3명. 비침습 측정. 수업 과제 범위의 자가 실험이므로 동의 확인만 받고 기록 |
| 장착 | 오른쪽 정강이 바깥쪽, 발목에서 1/3 높이. 보드 X가 아래, 부품면이 바깥을 향하게 벨크로로 고정. STM32는 허리 또는 주머니, USB 연장선 |
| 보행 | 트레드밀 4 km/h 60 s × 2–3회. 트레드밀이 없으면 복도 10 m 왕복을 60 s 동안 (방향 전환 구간은 분석에서 제외) |
| 촬영 | 측면 2–3 m, 100 fps(또는 120), 다리 전체와 동기 LED가 화면에 같이 들어오게. 조명을 밝게 |
| 동기 | `log_serial.py --sync`: 시작 1 s 후와 끝 1 s 전에 LED + SYNC 펄스. 리그는 `P0`(정지)으로 둔다 |
| 주석 | `python video_events.py led video.mp4 --out ../data/E4_S1_t1_video.csv` → `annotate`로 HS(뒤꿈치 첫 접촉)·TO(발끝 이지) 프레임 표시. 60 s에 30분 정도 |
| 분석 | `python analyze.py gait ../data/E4_S1_t1.csv --video ../data/E4_S1_t1_video.csv --out ../results/E4` |
| 성공 기준 | HS 매칭 40개 이상/회. E3의 d\* 경향(어느 계열이 빨리 사후 수준에 닿는가)이 유지된다 |
| 한계 (발표에 명시) | 100 fps 영상의 해상도는 ±10 ms (프레임 1장). 그래서 사람 실험은 "지연 순위가 유지되는가"를 보는 용도이고, 정밀한 수치는 E3에서 얻는다 |

### E5. MCU 연산 비용 (빠르게)

- STM32에 `c`를 보내 필터별 1샘플 처리 시간(µs)을 읽는다. E3 기록 직후에 받는다.
- 선택: 같은 구조체를 Uno에 옮겨 시간을 잰다. 고정지연 칼만이 8 bit MCU에서 가능한지 보는 용도.

## 3. 분석 지표 (발표에서 쓰는 정의)

| 지표 | 정의 | 의미 |
|---|---|---|
| **실효 지연** (ms) | 각 처리의 HS 시점 평균 − 사후(영위상) 처리의 HS 시점 평균 | 실시간 처리가 사후보다 얼마나 늦게 HS를 내는가. 서보 지연이나 영상 판정 기준처럼 일정한 치우침은 빠진다 |
| **지터** (ms) | HS 시점 오차의 표준편차 | 검출이 보폭마다 얼마나 흔들리는가 |
| **파형 오차** (deg/s) | 지연을 보정한 뒤 사후 기준 신호와의 RMSE | 모양이 얼마나 사후와 같은가 |
| **사후 수준** | 지터 ≤ 사후 지터 × 1.1 + 1 ms, **그리고** 파형 오차 ≤ 원신호 파형 오차 × 0.3 | 원신호가 사후 결과와 다른 정도를 70 % 이상 줄였다 |
| **d\*** | 실시간 처리 중 사후 수준을 만족하는 **가장 작은 실효 지연** | "이 정도만 기다리면 충분하다" |
| **흔들림** | 정지 구간 표준편차, 피크-피크, 0.1 s 창 RMS | 데모와 E1·E2 |
| 통계 | 보폭별 HS 오차로 Friedman 검정 → 사후와 Wilcoxon 대응 비교(Holm 보정) | 차이가 우연이 아님을 보임 |

판정 기준(1.1, 0.3)은 실험 전에 고정하고 발표에도 적는다. 결과를 보고 기준을 바꾸지 않는다.

## 4. 일별 상세 계획

시간은 하루 8–10시간 작업을 기준으로 잡았다. 3D 출력은 기다리는 시간이 길어서 **출력 중에 다른 일을 병렬로** 하도록 배치했다.

## 7. 예상 질문

1. **고정지연이면 결국 늦는 것 아닌가?**
   늦는다. 핵심은 "얼마나"다. 보조 장치의 허용 지연(예: 50 ms) 안에서 사후와 같은 정확도를 낼 수 있는지 수치로 보인 것이 기여다.
2. **참값이 명령 펄스인데 서보가 늦게 따라가지 않나?**
   일정한 지연은 사후 기준 대비 중앙값으로 빼고, 남는 것은 필터 몫이다. 서보 지연 자체는 영상으로 따로 쟀다 (D3 오전 측정값).
3. **100 fps 영상으로 10 ms 차이를 구분할 수 있나?**
   사람 실험은 순위가 유지되는지를 보는 용도다. 정밀한 수치는 µs 단위로 타임스탬프한 벤치(E3)에서 얻었다.
4. **1€ 필터의 고정지연 버전은 표준인가?**
   아니다. 전·후방 평균으로 만든 제안 변형이고, 발표에서 그렇게 밝힌다.
5. **칼만 q, R은 어떻게 정했나?**
   R은 E1 정지 분산이다. q는 RTS의 −3 dB가 Butterworth와 같은 10 Hz가 되도록 정했다 (계열 간 공정 비교).
6. **왜 fc = 10 Hz인가?**
   보행 정강이 각속도의 주요 성분은 대부분 10 Hz 아래에 있다 (예비 시뮬레이션, 보행 분석에서 흔히 쓰는 6–15 Hz 범위). 다른 fc는 선택 실험으로 남긴다.
7. **AAF를 켜면 그 자체도 지연이 있지 않나?**
   있다. MPU-6050 데이터시트 기준 DLPF_CFG = 3(자이로 42 Hz)에서 약 4.8 ms다. 그래도 접힌 잡음은 뒤에서 못 지우므로 켜는 것이 맞다는 것이 E2의 결론이다.
8. **MCU에서 실제로 돌아가나?**
   STM32에서 필터별 µs 단위 처리 시간을 측정했다 (E5 표).
9. **다른 사람, 다른 속도에서도 같은가?**
   한계로 둔다. 피험자 수와 속도 조건 확장이 후속 연구다.
10. **이벤트 검출 규칙이 결과에 영향을 주지 않나?**
    모든 필터에 같은 규칙(mid-swing 뒤 첫 극소)을 적용했다. 규칙은 실험 전에 고정했다.

## 9. 위험 관리

| 위험 | 가능성 | 영향 | 대응 |
|---|---|---|---|
| 3D 출력 실패 (휨, 중단) | 중 | 리그 지연 | 타워를 0.28 mm 초안 품질로 다시 출력(약 4.5 h). 급하면 MDF 판에 서보 구멍만 뚫어 대체 |
| 서보 기어 파손 (충격) | 중 | E3 C2–C4 불가 | 금속 기어 사용, 예비 서보 준비. 파손되면 충격 없는 조건(C1)과 진동 조건으로 대체 |
| I²C 오류 (선 길이, 진동) | 중 | 데이터 끊김 | 100 kHz로 낮춤, 선을 꼬아 짧게, 풀업 4.7 kΩ 추가 |
| 진동 앨리어싱이 안 보임 | 중 | E2 설득력 약함 | PWM 조정, 1 kHz 스펙트럼과 계산식으로 설명 |
| 사람 실험 영상 동기 실패 | 중 | E4 수치 불확실 | 발 구르기 동기, 또는 E4를 정성 비교로 축소 |
| 영상 주석 시간 부족 | 높음 | E4 지연 | 회당 30 s만 주석 |
| 데모 당일 COM 포트·드라이버 문제 | 중 | 데모 실패 | 리허설한 노트북 그대로 사용, 백업 영상 |
| 분석 결과가 가설과 다름 (예: 1€가 가장 좋음) | 중 | 결론 변경 | 결과대로 결론을 쓴다. 판정 기준은 사전에 고정했으므로 그대로 보고 |
